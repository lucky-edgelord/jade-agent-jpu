TRINITY//256

Free in-browser simulator for the Trinity-256 RISC-V + Xtrinity neural ISA. Write assembly, step through it, step back, set breakpoints, and watch registers, SRAM and machine code change. The NVDLA GEMM, Coral MAC/activation and NoC reduce engines do real arithmetic.

Emulator ABI v1 (spec gaps, filled in)

  • NVDLA.GEMM: K comes from x15. A (INT8 M×K) at Tile SRAM 0x1000, B (INT8 K×N) at HBM 0, C (INT32 M×N) written at Tile SRAM 0.
  • CORAL.ACT: R[rs1] is a Tile SRAM address (base 0x00200000); it runs in place over the last GEMM's M×N elements. Values are INT32 milli-units.
  • CORAL.MAC: A tile at R[rs1], B at R[rs2], 16×16 INT32 result at R[rs1]+0x1000.
  • NOC.REDUCE: tiles 1–3 are preloaded with .shard.

Preload directives (this simulator)

  • .sram OFFSET v,v,… INT8 bytes into Tile SRAM · .hbm OFFSET v,… INT8 bytes into HBM · .shard TILE OFFSET w,… 32-bit words into shard tile 1–3's SRAM.

Address map

  • ITCM 0x0000 8 KB · DTCM 0x8000 32 KB · NVDLA CSB 0x100000 · Tile SRAM 0x200000 2 MB · Quad SRAM 0x1000000 4 MB · Semaphores 0x1400000 · HBM 0x800000000000 (4 MB window modelled)

Syscalls

  • ECALL with a7 = 1 prints a0 (signed) to the console. Any other a7 halts.

Bytes written by the last instruction are highlighted.

How to run Trinity-256 assembly online

  1. Pick an example, or type assembly. Use .sram / .hbm directives to preload matrices.
  2. Press Run to execute, or Step to go one instruction at a time. Back undoes it exactly.
  3. Open Machine code to see each instruction's address, hex word and run count; copy or download it.

Tips for debugging

  • Set a breakpoint before an engine instruction, then inspect Tile SRAM after stepping over it.
  • The console warns whenever the spec's missing details (gaps G1–G5) change the result, e.g. GEMM with x15 = 0.
  • Immediates are 12-bit; build larger constants with LUI + ADDI.
