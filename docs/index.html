Trinity-256

A heterogeneous neural superchip — 256 tiles, each pairing a RISC-V control core with a Coral NPU and an NVDLA tensor engine. This repo holds a working ISA emulator and the hierarchical SystemVerilog RTL, both corrected against the architecture manual.

At a glance

Headline numbers at 1.2 GHz, 3 nm (from the specification).

256tiles: 4 chiplets × 16 quads × 4 tiles
471.9peak INT8 TOPS (314.6 NVDLA + 157.3 Coral)
768 MBon-package SRAM (256×2 MB + 64×4 MB)
9.6 TB/saggregate HBM3E bandwidth, 8 stacks
<15 W – 300 WP3 sentinel standby to P0 full saturation

Hierarchy

Four levels, each with its own interconnect.

Emulator

One file, standard library only. It assembles text to 32-bit words, decodes them, and executes against real state — the engines do real arithmetic.

python3 emulator/trinity_emu.py            # self-tests + demos
python3 emulator/trinity_emu.py prog.asm   # assemble + run

NVDLA.GEMM  INT8 MxK  x  INT8 KxN  ->  INT32 MxN
CORAL.MAC   16x16 INT8 tiles       ->  16x16 INT32
CORAL.ACT   ReLU / SwiGLU / Softmax / RMSNorm
NOC.REDUCE  sum a word across up to 4 simulated tiles

The spec leaves gaps (no K dimension for GEMM, no tensor length for ACT, and so on). The emulator defines an explicit Emulator ABI v1 for them and logs a warning whenever one matters.

What was fixed

AreaProblem → fix
EMULUINot sign-extended. Now sext(imm20<<12) per the manual.
EMUNOC.REDUCEIgnored R[rs2]. Now sums that many shards (0 = all 4); bounds-checked.
EMUCoral TCMOne flat 64 KB buffer. Now 8 KB ITCM @ 0x0 and 32 KB DTCM @ 0x8000; the gap faults.
EMUSemaphoresNo doorbell. Now armed flag + doorbell at zero; CORAL.ACT no longer consumes counts.
EMUBoundsCORAL.MAC output tile and GEMM sizes checked; illegal instructions halt cleanly.
RTLQuad crossbarAcked every requesting tile. Now only the granted one.
RTLQuad SRAMWrites clobbered all 4 lanes. Now byte-enabled per lane.
RTLRead timingData returned in the request cycle despite 1-cycle SRAM latency. Responses now registered.
RTLHBM flagdst_quad==0xF collided with real Quad 15. Replaced by a gw_hbm bit; flit is exactly 1024 bits.
RTLRemote accessCoordinate bits bounced requests back up the uplink. Now the 32-bit local offset is used.
RTLAllReduceAccumulator never cleared. Now absorbs N contributions, emits the sum, resets.
RTLGateways / UCIeFlits circled the torus; rows 2–3 had no HBM path; UCIe ingress was missing; diagonal traffic duplicated. All fixed.
RTLSRAM & clocksDual-writer always_ff is illegal; clk & en glitches. Now plain always and a latch-based clock gate.

Known limitations

  • The torus router has no input FIFOs or credit flow control, so simultaneous transit flits collide.
  • There is no read-response path for global NoC or HBM reads.
  • hbm_req_addr is 34 bits; 288 GB of HBM needs 39.
  • P1 power state is identical to P0 (HBM self-refresh not modelled).
  • The RTL lints clean but has not been simulated.
